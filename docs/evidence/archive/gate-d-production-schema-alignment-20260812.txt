## 5) إثبات التطابق النهائي

طريقة الإثبات: بصمة مخطط شاملة تُوَلَّد بنفس استعلام SQL على القاعدتين
وتغطّي — لكل كائن في مخطط public عدا spatial_ref_sys:
  الأعمدة وأنواعها وقابلية NULL والقيم الافتراضية،
  كل القيود (PK/FK/UNIQUE/CHECK) بنصّها الكامل،
  كل الفهارس بنصّها الكامل،
  حالة RLS لكل جدول،
  كل سياسة RLS: الأمر، الأدوار، using، with check،
  كل دالة: التوقيع، definer/invoker، proconfig (search_path)، md5 لجسمها.

المرجع المحلي: 842 سطر بصمة (قاعدة مبنيّة من الـ34 هجرة بالترتيب)
الأمر:  diff local-fp.clean prod-fp.clean
النتيجة النهائية بعد استثناء دوال الامتدادات (pgcrypto / uuid-ossp / postgis
الموجودة في مخطط extensions على Supabase وفي public محلياً، واختلاف إصدار
PostGIS 3.3.7 مقابل 3.6):
  صفر فروق على مستوى التطبيق — لا جدول، لا عمود، لا قيد، لا فهرس،
  لا سياسة RLS، لا دالة تطبيقية.

## 7) حالة spatial_ref_sys — مُخفَّفة ومقصودة لا ثغرة مفتوحة

تنبيه Supabase الأمني يشير إلى rls_disabled_in_public على
public.spatial_ref_sys. الجدول مملوك لامتداد postgis ولا يمكن تفعيل RLS
عليه من دور غير خارق. البند ٣ من هجرة 20260809000000 يعالج ذلك بقفل جامع
أقوى: سحب usage على مخطط public من anon و authenticated.

الإثبات على الإنتاج:
  has_schema_privilege('anon','public','usage')          → false
  has_schema_privilege('authenticated','public','usage') → false
  has_schema_privilege('service_role','public','usage')  → true
  has_schema_privilege('postgres','public','usage')      → true

الصلاحيات المتبقّية لـ anon/authenticated في public:
  الجداول: geography_columns, geometry_columns, spatial_ref_sys — ثلاثة
    كائنات مملوكة لامتداد postgis وحدها، وصفر جدول تطبيقي.
  الدوال: كلها دوال postgis (‎_st_*, st_*, box*, addgeometrycolumn …)‎،
    وصفر دالة تطبيقية.
  وكلها غير قابلة للوصول أصلاً لانعدام usage على المخطط.

طريقة العرض agent_effectiveness:
  reloptions → {security_invoker=true}  (لم تعد security definer ضمناً)

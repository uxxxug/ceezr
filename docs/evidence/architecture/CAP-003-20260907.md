# دليل CAP-003 — نقل المطابقة إلى استعلام PostGIS واحد

> **التاريخ:** 2026-09-07
> **البند:** CAP-003 (ونظيره F7-01)
> **النوع:** صحيح (correctness) + معماري (architecture)
> **الحالة:** مُنفَّذ ومُختبَر وحدويّاً؛ التحقّق التكامليّ على PostGIS في CI.

---

## ١. العطب قبل الإصلاح

`findAvailableInCity(cityId)` في
[`packages/infrastructure/dispatch/dispatch-adapters.ts`](../../../packages/infrastructure/dispatch/dispatch-adapters.ts)
كان يستعلم:

```sql
select ... from drivers d join users u ... where d.city_id = ${cityId}
```

أي يحمّل **كلّ سائقي المدينة** إلى الذاكرة بفلترة `city_id` وحدَه، ثمّ يترك للدومين
`evaluateCandidates` أن يُرشِّح بالمسافة والتوفّر والتوثيق والخدمة والاشتراك. وفهرس
GiST `drivers_location_gix` (الموجود منذ المرحلة 2.1) **غير مستخدم**: لا `ST_DWithin`
ولا ترتيبٌ مكانيٌّ، فيُمسحُ الجدولُ كاملَه. مع نموّ السائقين تصيرُ القراءةُ هي العنق.

## ٢. الحلّ

مسارٌ سريعٌ جديدٌ `findNearbyAvailableForDispatch(args)` — استعلام PostGIS واحد:

| البوابة | في SQL | في الدومين |
|---|---|---|
| المدينة `city_id` | ✅ | — |
| الحجب `users.is_blocked = false` | ✅ | — |
| التوثيق `verification_status = 'verified'` | ✅ | — |
| التوفّر `is_available = true` | ✅ | — |
| القرب `ST_DWithin(last_location, pickup, radius)` | ✅ | — |
| عمر الموقع (إن فُعّل، صفر = تعطيل) | ✅ | — |
| الاستبعاد هذه الدورة `EXCLUDED_THIS_ROUND` | ❌ (يُترك للدومين) | ✅ |
| الخدمة `SERVICE_NOT_ENABLED` | ❌ | ✅ |
| الاشتراك `NO_LIVE_SUBSCRIPTION` | ❌ | ✅ |
| الترتيب بالمسافة `ORDER BY last_location <-> pickup` | ✅ (KNN عبر GiST) | — |
| الترتيب النهائي بالـscore | — | ✅ |
| اختيار دفعة البثّ | — | ✅ |

**الترتيب النهائي:** `ORDER BY d.last_location <-> pickup_geography LIMIT k` — عامل `<->`
هو KNN distance الذي يستخدم فهرس GiST مباشرةً.

### لماذا الخدمة والاشتراك لم يُفلترا في SQL

منطقُ الاشتراك معتمدٌ على `now` وعلى خريطة `plan→service` (انظر
[`coversService`](../../../packages/domain/subscription/entity.ts) و
[`isSubscriptionLive`](../../../packages/domain/subscription/entity.ts)). تكرارُهما
في SQL خطرُ انحرافٍ صامتٍ يوم يتغيّر أحدُهما. والدومينُ يفلترُهما فوق نافذةٍ
محدودة (الإعدادُ `matching_candidate_limit`، مبذورٌ ٥٠) — أوسعُ من دفعة البثّ (٥)
عمداً، كي لا يفوتَ مؤهَّلٌ أبعدُ بسببَ امتلاء النافذة بغير المؤهَّلين قبلَه.

### لماذا الاستبعاد لم يُفلتر في SQL

الاستبعادُ (`EXCLUDED_THIS_ROUND`) قرارٌ تشغيليٌّ يُرى في `rejected` بسببه المُسمّى
— والمشغّلُ يحتاجُ أن يعرفَ أنّ السائقَ مشغولٌ هذه الدورة لا أن يختفيَ صامتاً.
والسائقون المستبعدون قلّةٌ (محدودون بعدد العروض هذه الدورة)، فتكلفةُ إبقائهم
للدومين ضئيلة، ويرثُهم `rejected` مباشرةً.

## ٣. التراجع التشخيصي عند انعدام المؤهَّلين

عندما تُفرغُ النافذةُ القريبة من المؤهَّلين (بعد فلترة الدومين للخدمة والاشتراك)،
يرجعُ `matchOrder` إلى `findAvailableInCity` **كمسارٍ تشخيصيٍّ وحده** — لا في
التشغيل الطبيعي. هذا المسار يبني قائمةَ الرفضِ المُسبَّبة كاملةً، فيظهرُ:

- السائقُ بلا موقع بسببه `NO_LOCATION` (لا يدخلُ المسارَ السريعَ لأنّ `ST_DWithin`
  على NULL يُرجعُ NULL فيُستبعدُ — فلا يُفقدُ، يُؤجَّلُ للتشخيص).
- السائقُ خارجُ نصف القطر بسببه `OUT_OF_RADIUS`.
- السائقُ غيرُ متاحٍ بسببه `NOT_AVAILABLE`.

وهذا أيضًا **حارسُ صحّةٍ**: لو فاتَ المسارَ السريعَ مؤهَّلٌ أبعدُ (خارجَ حدِّ
النافذة `LIMIT k`) يجده هذا الاستعلام فيظهرُ في `eligible` لا في `rejected`.

## ٥. فهرس GiST

الفهرس موجودٌ منذ المرحلة 2.1 وغيرُ مستخدمٍ قبلَ هذا العمل:

```sql
create index if not exists drivers_location_gix on drivers using gist (last_location);
```

المسارُ السريعُ يستخدمُه عبر `ST_DWithin` (فلترة مكانية) وعبر `<->` (ترتيب KNN).
خطّةُ `EXPLAIN` المُتحقَّقُ منها في الاختبار التكامليّ السابع:

```sql
set enable_seqscan = off;
explain (format text)
  select d.id from drivers d
   where d.city_id = $1
     and st_dwithin(d.last_location, $2, 10000)
   order by d.last_location <-> $2
   limit 50;
```

تُطابقُ الخطةُ نمطَ `Index Scan using drivers_location_gix` أو `Bitmap Index Scan`.

### تكاملية (على PostgreSQL/PostGIS 17-3.5 حقيقي)

`tests/integration/dispatch-nearby-candidates-postgis.test.ts` — ٧ حالات:

1. لا يُرجعُ إلا داخلَ نصفِ القطرِ متاحاً موثَّقاً غيرَ محجوبٍ، مرتّباً بالمسافة.
2. `driverLocationMaxAgeSeconds = 0` يُعطّلُ فحصَ القِدَم (المرحلة ٨).
3. عند التفعيل، الموقعُ القديمُ يُستبعدُ.
4. `last_location = NULL` لا يدخلُ النتيجة.
5. `LIMIT` يحدُّ النتيجةَ بعدَ البواباتِ الصلبةِ (لا يمتلئُ بغيرِ الصالحين).
6. الترتيبُ بالمسافةِ تصاعديّاً.
7. خطةُ `EXPLAIN` تكشفُ استخدامَ `drivers_location_gix`.

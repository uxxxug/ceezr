## ١) العيبُ بحرفِه

في المسارِ الإنتاجيِّ — حيثُ `deps.intake` موصولٌ دائماً (`apps/gateway/src/index.ts`) —
كان الشرطُ الحاكمُ لفحصِ التكرارِ والإيداعِ يقتضي `updateId !== null`. فحين تصلُ حمولةٌ
بلا `update_id` صالحٍ (غائبٌ، أو نصٌّ، أو عددٌ غيرُ صحيحٍ موجبٍ) كان الشرطُ يفشلُ
**فيسقطُ التنفيذُ إلى `handler.handle` داخلَ طلبِ HTTP**.

وهذا ينقضُ [ADR 0054](../../adr/0054-telegram-webhook-durable-ingest-and-dedup.md) §٦
نصّاً: «العملُ الذي يلي الإيصالَ… لا يُنفَّذ داخلَ طلبِ HTTP». فالفجوةُ **مسارُ التفافٍ
على الـingest النحيفِ** يُفتحُ بحمولةٍ مُشوَّهةٍ يرسلُها أيُّ طرفٍ يعرفُ سرَّ الويبهوكِ.

## ٢) الحُجَّةُ المرجعيّةُ لِمَ الرفضُ لا المعالجةُ

[Telegram Bot API — Update](https://core.telegram.org/bots/api#update) يُعرِّفُ `update_id`
(Integer) **الحقلَ الإلزاميَّ الوحيدَ** في كائنِ `Update`، وكلُّ ما عداه اختياريٌّ. فحمولةٌ
بلا `update_id` صالحٍ **ليست تحديثَ تيليجرام**، ولا مفتاحَ لها يُمنَعُ به التكرارُ، ولا
يجوزُ إيداعُها في الطابورِ الصامدِ (مفتاحُ `telegram_update_receipts` الأوّليُّ هو
`(bot, update_id)`). فلا بقيَ إلَّا الرفضُ.

## ٣) المُنفَّذ

**ملفٌّ واحدٌ في مسارِ الإنتاجِ** — `apps/gateway/src/routes/telegram-webhook.ts`:
حارسٌ واحدٌ بعدَ استخراجِ `updateId` وقبلَ الإيصالِ الصامدِ:

```ts
if (deps.intake !== undefined && updateId === null) {
  return c.json({ ok: false, error: "INVALID_UPDATE" }, 400);
}
```

**والحصرُ بـ`deps.intake !== undefined` مقصودٌ لا تهاونٌ**: مسارُ الاختبارِ/التشخيصِ
(حيثُ `intake === undefined`) يبقى سلوكَهُ المُعلَنَ بلا تغييرٍ، فلا يُعادُ كتابةُ مساعداتِ
الاختبارِ ولا يُمَسُّ عقدٌ قائمٌ. **وترتيبُ ADR 0054 محفوظٌ**: الحارسُ بعدَ تحقُّقِ السرِّ
وبعدَ حدِّ المعدَّلِ، لا قبلَهما — فلا يُصبحُ الحارسُ نفسُه بابَ تجاوزٍ لحدِّ المعدَّلِ.

## ٤) الاختبارُ

`tests/unit/telegram-webhook-production-guard.test.ts` — ثلاثُ حالاتٍ:

1. **الإنتاجُ (`intake` موصولٌ) يرفضُ `400` حمولةً بلا `update_id`** — ويُثبَتُ
   بمعالجٍ متتبِّعٍ وإيداعٍ متتبِّعٍ أنَّ **المعالجَ لم يُنادَ ولا مرّةً والإيداعَ لم يُنادَ ولا مرّةً**
   (`handlerCalls = 0` و`enqueueCalls = 0`) — فالاختبارُ يحكمُ بنتيجةِ العملِ لا بكودِ HTTP وحدَه.
2. **الإنتاجُ يرفضُ `400` حمولةً بـ`update_id` غيرِ صحيحٍ** (`"not-a-number"`) — بالتوكيداتِ نفسِها.
3. **مسارُ الاختبارِ (بلا `intake`) يُعالجُ الحمولةَ بلا رفضٍ** (`200`، والمعالجُ نُوديَ مرّةً)
   — **اختبارُ ضبطٍ سالبٍ** يمنعُ أن يتسرَّبَ الحارسُ إلى غيرِ نطاقِه.

## ٥) النتائجُ المقيسةُ محلّيًّا (Bun 1.4.2، 2 vCPU، بلا قاعدةٍ حقيقيّةٍ)

| الفحصُ | النتيجةُ |
|---|---|
| `bun run lint` (biome 2.5.7) | `0` — لا خطأَ ولا تحذيرَ تنسيقٍ |
| `bun run typecheck` (`tsc --noEmit` × جذرٌ + miniapp) | `0` |
| `bun test` | **٢٢١٠ ناجحاً · ٦٣٦ متجاوَزاً · ٠ فاشلاً · ٦٩٤٩ توكيداً في ٢١٧ ملفّاً** |

**وحدُّ البيئةِ مُعلَنٌ**: لا Redis ولا PostgreSQL حقيقيّانِ في هذا الصندوقِ، فالمتجاوَزُ
(٦٣٦) هو حزمةُ التكاملِ الحقيقيِّ — وحكمُها في CI لا هنا.

**وتصحيحٌ في هذه الوحدةِ**: كانت وظيفةُ `verify` على الفرعِ **حمراءَ** لسببٍ واحدٍ هو
**تنسيقُ** ملفِّ الاختبارِ الجديدِ (`biome format`)، لا منطقاً ولا نوعاً. أُصلِح بـ
`biome format --write` على ذاك الملفِّ وحدَه.

## ٦) ما لم يُمَسّ — يُقرأُ حرفيّاً

- **لا بندَ في `ROADMAP-MASTER` قُلِبَ** — `F6-01`/`CAP-001` كانا `[x]` وبقيا، وهذا **إصلاحُ
  عيبٍ داخلَ بندٍ مُغلَقٍ لا قلبُ حالةٍ**، فقاعدةُ `ح-4` (ثلاثُ جولاتٍ خضراءُ للقلبِ) غيرُ
  مُستحَقَّةٍ ههنا — والمُشترَطُ خضرةُ وظائفِ CI الثلاثِ قبلَ الدمجِ (القاعدةُ 0.7 من التوجيهِ).
- **لا نصُّ بندٍ عُدِّل (`ح-1`) ولا `ADR` منشورٌ عُدِّل (`ح-6`)** — `ADR 0054` و`ADR 0057`
  قائمانِ، والإصلاحُ **يُوافقُ** §٦ منهما لا يُخالفُه.
- **لا هجرةَ ولا حاجزَ ولا تغييرَ في مخطَّطِ القاعدةِ** — ولا `city_id` ولا `RLS` مُسَّ.
- **لا `SCL-*` ولا `F6-03` ولا `R-17` ولا Socket.IO ولا `DEC-11` ولا `F0` مُسَّ.**
- **لا `مَقيس` ولا `مُثبَت` (`ح-5`)** — المُتحقَّقُ منه أنَّ الحمولةَ المُشوَّهةَ لا تصلُ المعالجَ
  ولا الطابورَ في مسارِ الإنتاجِ، **لا** throughputُ الإنتاجِ ولا latencyُ الويبهوكِ ولا
  سلوكُ تيليجرام الحقيقيُّ.

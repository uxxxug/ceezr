## هذا الإغلاقُ مُركَّبٌ لا جديدُ كودٍ

F5-03 لم يحتجْ إلى كودٍ إنتاجيٍّ جديد، لأنَّ متطلبه النصّيَّ (فحصُ إقلاعٍ يفشلُ في الإنتاجِ حين يكونُ `SESSION_STORE=memory`) **مُنفَّذٌ بالكاملِ عبر `SCL-002`** المُغلَقِ بـ`[x]` في التشغيلِ `34054604942` على `619942f`.

## الدليلُ من الكودِ الفعليِّ

`packages/shared/config/index.ts` (السطر 491)، داخلَ `tryLoadConfig`:

```ts
if (env === "production" && rawSessionStore === "memory") {
  return err(
    new InvalidEnvVarError(
      "SESSION_STORE",
      "memory غير مسموحٍ في الإنتاج — جلساتُ الذاكرةِ تُمحى بإعادةِ التشغيلِ وتُفقدُ خطواتٍ عندَ التزامنِ بلا CAS. اضبط SESSION_STORE=redis",
    ),
  );
}
```

- `env` مشتقٌّ من `NODE_ENV` (السطر 397): `"production"` يمرُّ كما هو، وما عدا `production`/`test` يُعدُّ `development`.
- `rawSessionStore` قيمةُ `SESSION_STORE` الخامُ، افتراضُها `"memory"` حين يغيبُ المفتاحُ (السطر 472).
- الفشلُ يقعُ في `tryLoadConfig` قبلَ أن يبدأَ الخادمُ، فيخرجُ `apps/gateway/src/index.ts` بـ`process.exit(1)` برسالةٍ معلنةٍ (السطر 109-113: `topologyViolation`/`tryLoadConfig` error → `console.error` + `exit(1)`).

## مطابقةُ المتطلبِ بالنصّ

| نصُّ F5-03 | المُنفَّذُ في SCL-002 | مطابق؟ |
|---|---|---|
| «Redis إلزاميٌّ في الإنتاج» | الإنتاجُ لا يقلعُ إلّا بـ`SESSION_STORE=redis`؛ `memory` مرفوضٌ | ✓ |
| «فحصُ إقلاعٍ يفشلُ» | `tryLoadConfig` يُعيدُ `InvalidEnvVarError` قبلَ تجميعِ `AppConfig` | ✓ |
| «إذا كان `SESSION_STORE=memory`» | الشرطُ `env === "production" && rawSessionStore === "memory"` يشملُ القيمةَ الصريحةَ والغيابَ (الافتراضُ `memory`) | ✓ |

## الاختباراتُ القائمةُ التي تُؤكّدُ المتطلَّبَ (من SCL-002، `tests/unit/config-session-store.test.ts`)

- الإنتاجُ + `memory` ⇒ فشلٌ (`InvalidEnvVarError`).
- الإنتاجُ + غيابُ `SESSION_STORE` (يفترضُ memory) ⇒ فشلٌ.
- الإنتاجُ + `redis` ⇒ نجاحٌ.
- التطويرُ/الاختبارُ + `memory` ⇒ مسموحٌ.

كلُّها خضراءُ في التشغيلِ `34054604942` على `619942f` (بوظائفِه الثلاثِ).

## لماذا لا حاجةَ إلى كودٍ جديدٍ أو حارسٍ إضافيٍّ

- حارسُ الإقلاعِ في `tryLoadConfig` يضمنُ بالفعلِ أنَّ الإنتاجَ لا يقلعُ بـmemory. إضافةُ فحصٍ ثانٍ في `index.ts` تكرارٌ لما يضمنُهُ حارسُ الإعداداتِ قبلَه.
- متغيراتُ `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN` مفروضةٌ في `REQUIRED_ENV_KEYS`، فعميلُ Redis جاهزٌ دائمًا في الإنتاجِ — لا فحصُ صلاحيةٍ إضافيٌّ يُحتاج.

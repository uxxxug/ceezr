# دليلُ `SCL-005` — مخزنُ البثّ المشترك + الادّعاءُ الذرّيُّ لبدءِ البثّ (2026-09-08)

## البندُ

`SCL-005`: «خريطةُ `tripId → messageId` للبثّ الحيّ في الذاكرة» — نصُّ الحلّ:
«جدول/مفتاح مشترك، أو إسقاطُ الحاجةِ كليّاً بعدَ انتقالِ التتبّع إلى Mini App».

## القرارُ الحوكميُّ

**اعتمدَ صاحبُ المشروعِ المسارَ «مفتاحٌ مشترك»** (لا «إسقاطُ الحاجةِ» — فـ`F4-07`
المستقبليُّ `[ ]` يعتمدُ انتقالَ Mini App غيرَ المُنجَز، فلا يُغلَقُ بندٌ بـ«التزامٍ
مستقبليٍّ» يقلبُ حالةً بلا تحقق). والتفاصيلُ في
[ADR-0060](../../adr/0060-scl-005-redis-shared-broadcast-store.md).

## ما نُفِّذ

### ١. واجهةُ `LiveBroadcastStore` + تنفيذانِ

- **الواجهة** `packages/application/tracking/live-broadcast-store.ts`: `get`/`save`/
  `delete`/`claimStart`/`releaseClaim` + نوعُ `BroadcastState`.
- **الذاكرة** `packages/application/tracking/in-memory-live-broadcast-store.ts` — للاختبارِ
  والتطويرِ بلا Redis (افتراضيٌّ حين لا يُمرَّرُ مخزنٌ).
- **Redis** `packages/infrastructure/tracking/redis-live-broadcast-store.ts` — عبرَ عميلِ
  Upstash REST نفسِه (`RedisClient.command`): `GET`/`SET PX`/`DEL`/`SET NX PX` (الادّعاءُ)
  و`EVAL` (التحريرُ الآمنُ بـLua: `if get == token then del`).

### ٢. إعادةُ هيكلةِ المُرحِّلِ (`customer-live-relay.ts`)

- استُبدِلَت خريطةُ `Map<string, Broadcast>` بالمخزنِ المُحقَن. و`openBroadcasts` صارَ
  عدّاداً محليّاً (`Set<string>`) للبثّاتِ التي تُديرُها هذه النسخة.
- **بدءُ البثّ صارَ يُدّعى ذرّيّاً**: `claimStart(tripId, token, ttl)` بـ`SET NX` — إن نجحَ
  نادى `channel.start` وحفظَ الحالةَ في المخزن، وإلّا تخطّى (الحدثُ التالي يلتقطُ الحالةَ).
  التحريرُ في `finally` بالرمزِ الآمن.
- الكتابةُ عندَ البدءِ والإغلاقِ والتشوهِ (`update` فشلَ فنُسيَت الرسالة) فقط — لا لكلِّ
  إصلاحة. فيتفادّى ثمنَ الكتابةِ لكلِّ تحديثٍ.
- كلُّ الثوابتِ القائمةِ حُفِظَت: بوّابةُ الترتيبِ `BUG-009`، الخنطُ بالزمنِ والمسافة،
  إعادةُ اشتقاقِ الوجهةِ بعدَ حدّ الزمن، حرّاسُ الجلسة، `isTripLive`.

### ٣. التوصيلُ في `container.ts`

- `store: redis ? createRedisLiveBroadcastStore(redis) : undefined` — Redis حين يكونُ
  متاحاً (`sessionStore === "redis"`)، وإلّا الذاكرةُ (تنازلٌ موثَّقٌ كنشرِ نسخةٍ واحدةٍ).
- `newClaimToken: () => crypto.randomUUID()` — مُولِّدُ الرمزِ مُحقَنٌ حتى لا تستوردَ طبقةُ
  التطبيقِ `node:crypto` مباشرة.

### ٤. الاختبارات

- **15 اختبار وحدة** في `tests/unit/customer-live-relay-distributed.test.ts`:
  - مخزنُ الذاكرة: `get`/`save`/`delete`/`claimStart` (نجاحٌ مرّةً واحدة)/`releaseClaim`
    (آمنٌ بالرمز).
  - مخزنُ Redis بعميلٍ مزوّر: الادّعاءُ ذرّيٌّ، التحريرُ الآمن، ذهابٌ وعودةٌ، القيمةُ
    المشوّهةُ تعيدُ `null`، فشلُ الشبكة يعيدُ `false` لا يرمي.
  - مُرحِّلانِ يتشاركانِ مخزناً: أوّلُ حدثينِ متزامنينِ → `channel.start` مرّةً واحدة؛
    النسخةُ الثانيةُ تُعدِّلُ الرسالةَ نفسَها؛ الإغلاقُ من نسخةٍ أخرى يُوقفُ البثَّ مرّةً
    واحدة؛ التسلسلُ القديمُ يُتجاهَلُ.
- **اختبارُ تكاملِ Redis حقيقيّ** في `tests/real-redis/redis-sessions-real.test.ts`:
  ادّعاءٌ ذرّيٌّ تحتَ التسابقِ (عميلانِ معاً → واحدٌ يفوز)، ذهابٌ وعودةٌ، تحريرٌ آمنٌ، حذف.
  معرّفُ الفحصِ `scl-005-broadcast-shared-store` أُضيفَ إلى `REQUIRED_CHECKS`.

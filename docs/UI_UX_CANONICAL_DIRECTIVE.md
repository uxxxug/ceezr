## 0. القوانين الحاكمة (لا تُفاوض)

1. **الصدق أولًا:** لا رقم/حالة/زر/وعد بلا مصدر حقيقي. المجهول يُقال مجهولًا.
2. **لا تخترع ميزة:** حسّن القائم وفعّل ما له خادم جاهز [B]. لا تلمس الخادم إلا بموافقة [C].
3. **لا تكسر العقود:** `*contract.ts` و`*api.ts` و`*view.ts` تبقى. يتغيّر العرض فقط.
4. **CI خضراء قبل كل PR.**
5. **CSS مسطّح:** لا @layer، لا تداخل، لا !important. لا حذف قاعدة إلا بتسجيلها في RETAINED_RULES.
6. **لا مكتبات جديدة:** لا Framer Motion، لا مكتبة أيقونات، لا مكتبة واجهة. CSS و WAAPI فقط.
7. **الأمن للخادم:** لا تُضعف CSP/CSRF/authorization. الواجهة تعرض ولا تقرر.

## 1. الهوية

**Premium Utility** — حديثة، فاخرة، حية، هادئة، إنسانية، واضحة وسريعة.
لا Uber clone، لا Careem clone، لا glassmorphism، لا mesh gradients، لا confetti، لا radar.

## 2. الألوان (طبقتان)

**Layer 1 (محايدات تيليجرام):** من themeParams، تتبدّل مع سمة المستخدم.

`ui-btn` `ui-fld` `ui-tile` `ui-sg` `ui-chip` `ui-tag` `ui-pill` `ui-card` `ui-row` `ui-kv` `ui-truth` `ui-rail` `ui-timer` `ui-stp` `ui-sht` `ui-dg` `ui-tab` `ui-act` `ui-hdr` `ui-skel` `ui-empty` `ui-err` `ui-toast` `ui-banner` `ui-av` `ui-pl` `ui-st` `ui-ds` `ui-pg` `ui-copy`

كل مكوّن: React عرضي صرف في `src/system/ui/` + كتلة CSS مسجّلة في `DECLARED_BLOCKS`. عناصر دلالية (button, a, input) لا div. aria-label لكل أيقونة. تركيز ظاهر دائمًا.

## 5. الحالات (لا تُخلط)

Loading · Empty · Error · Refused · Unavailable · Stale · Unknown
كل حالة كاملة بصريًا (رسم + سبب + فعل).

## 6. التنقل

**الراكب:** الرئيسية · رحلاتي · الدعم · حسابي
**السائق:** العروض · مهمتي · أرباحي · حسابي
**التدفقات:** BackButton + action bar + ScreenTransition. لا tab bar داخل التدفقات.
`useScreenStack`: push / pop / replace / reset. تبديل التبويب يمسح stack.

## 7. الأداء

shell+identity ≤ 180KB gzip · CSS مدمج ≤ 40KB gzip · حزمة مؤجلة ≤ 120KB · ≤ 6 طلبات أول رسم.

## 12. القاعدة الحاكمة بين الوكلاء

«لا تدفع تغييرًا تنفيذيًا إلى المشروع منفصلًا عن تحديث الحالة وخارطة الطريق والوثائق التي تصف هذا التغيير.»

«لا توثّق شيئًا على أنه حقيقة إلا إذا كان مثبتًا بالدليل.»

### آلية الإنفاذ: manifest للوثائق المتأثرة

كل Work Packet يغيّر ملفات تنفيذية يجب أن يرفق manifest في
`docs/work-packets/*.json` يصرّح بـ:
- `implementation`: الملفات التنفيذية المتأثرة
- `state`: ملفات الحالة (SYSTEM_STATE.md)
- `roadmap`: ملفات الخارطة
- `affected_docs`: الوثائق المتأثرة بالتغيير
- `no_other_affected_docs_reason`: سبب إذا لم تكن هناك وثائق متأثرة

بوابة `check-state-sync` تتحقق من أن كل ملف تنفيذي مُصرّح به، وكل وثيقة
مُصرّح بها معدّلة فعلًا، وكل وثيقة معدّلة مُصرّح بها. لا تُعتمد على حسن
النية.

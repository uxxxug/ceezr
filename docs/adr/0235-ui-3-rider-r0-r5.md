# ADR 0235: UI-3 / PR 3 — وصلُ تجربةِ الراكبِ R0–R5

**الحالة:** مُنفَّذ على فرع `ui-3-pr3-rider-r0-r5`؛ لم يُدمج بعد
**التاريخ:** 2026-10-06
**المرحلة:** WASLA UI/UX REFOUNDATION — UI-3 (Rider Experience) · PR 3
**المرجع:** `docs/UI_UX_CANONICAL_DIRECTIVE.md` §§0، 5، 6، 9، 11 · ADR 0234
**Work Packet:** `docs/work-packets/ui-3-pr3-rider-r0-r5.json`

## القرار والنطاق

وصلت `RiderRoot` خطوات الراكب R0–R5 بهيكل UI-2 القائم، من غير إنشاء هيكل أو أصناف CSS موازية:

- `home` جذرٌ يحمل `ScreenFrame mode="root"` و`RootTabBar` ذي الوسوم المترجمة.
- `destination` و`quote` تدفّقان في `useScreenStack`، لكلٍّ منهما `ScreenFrame mode="flow"` ورجوع واحد من رأس الإطار؛ لا تمرير لـ`onBack` إلى الشاشة نفسها، ولا زر رجوع داخلي بلا فعل.
- اختيار الوجهة يدفع `destination`؛ قبولها يدفع `quote`. الرجوع من الاقتباس يعيد الوجهة، والرجوع منها يعيد جذر الرئيسية.
- عند تسليم نيّة الطلب من R5 إلى شاشة البحث R6، يُفرَّغ المكدّس وتُستعمل حالة `intent` القائمة؛ شاشات R6+ لم تتغيّر.
- تبويبات `rides` و`support` و`account` تسلّم إلى مسارات الحالة الموجودة (السجل والدعم والحساب)؛ لا تُنشأ لها شاشات أو بيانات وهمية. الوسوم الخمسة الجديدة موجودة باللغات العربية والإنجليزية والأردية.

ظلّ حاجز R0/R1 كما هو: `Shell` لا يركّب `RoleRouter` قبل نجاح الإقلاع، و`RoleRouter` لا يركّب سطحاً قبل اكتمال قراءة الدور وتحميل الحزمة والقاموس. الترحيب بوابة موافقة سابقة للجذر، وليس عضواً في مكدّس الخطوات.

## تدقيق الحالات R0–R5

الجدول يميّز الحالات المنطبقة على كل مرحلة؛ لا تُضاف حالات «قديمة/مرفوضة» أو أفعال لا يملكها مسارها:

| المرحلة | الحالات المنفّذة | المعلومة والفعل والتعافي |
|---|---|---|
| R0 — الإقلاع | `booting`، `ready`، شاشات سبب الرفض/التعذّر، ومنها بيانات فتح مفقودة أو قديمة، انقطاع الشبكة، تعطّل الخادم، والخطأ المجهول | `Skeleton` أثناء الفحص؛ ثم يسلّم إلى R1 أو يعرض سبباً مصنّفاً وفعل إعادة المحاولة حيث يكون قابلاً للمحاولة. حالة «خارج تيليجرام» لا تعرض إعادة محاولة كاذبة. |
| R1 — التسجيل/التوجيه | `resolving`، سطح تسجيل `onboarding` عند قرار الخادم، سطح دور منتج أو شاشة نظامية | لا سطح قبل القرار؛ قرار `routeForViewer` حتمي، ولا يُفترض دور عند غياب أو رفض الرد. |
| R2 — الترحيب والموافقة | تحميل، جاهز، رفض الموافقة، فشل نظامي، اكتمال من الخادم | يقرأ السجلّ أولاً؛ الإعادة آمنة ومعلنة عند الفشل. يُتجاوز الترحيب فقط إذا أثبتت القراءة الأولى اكتمال الموافقات على الخادم. |
| R3 — الرئيسية | تحميل، جاهز، بيانات فارغة للأماكن والوجهات الأخيرة، رفض API، فشل نظامي/شبكي | إعادة المحاولة متاحة للأخطاء القابلة لها. غياب مزوّد الخرائط معلن نصاً، لا يُستبدل بخريطة وهمية. |
| R4 — الوجهة | `idle`، `searching`، نتائج جاهزة أو فارغة، رفض البحث، `resolving`، قبول أو رفض التغطية، رفض الموقع، فشل نظامي | سبب الرفض والإجراء التصحيحي يختلفان بين رفض الإذن وخارج منطقة الخدمة. إعادة البحث متاحة حيث يصحّ ذلك؛ لا تُستبدل الإحداثيات المرفوضة بمركز مدينة مختلق. |
| R5 — الاقتباس/تهيئة الطلب | تحديد الموقع، طلب الاقتباس، رفض الموقع أو التغطية، نتيجة مقبولة، رفض API، فشل نظامي؛ قائمة خدمة فارغة لها نص معلن | أفعال المحاولة والإعدادات مرتبطة بسببها؛ معلومات الخدمة/المسافة/المدة لا تُعرض إلا من ردّ حقيقي، ولا يُختلق سعر نهائي أو دفع. زر طلب الخدمة موجود للخدمة المتاحة فقط. |

«فارغ» خاصٌّ ببيانات الرئيسية ونتائج البحث؛ «رفض» خاصٌّ بالموافقة أو بقرار الخدمة/الموقع؛ و«قديم/مجهول/شبكة/خادم» حالاتٌ نظامية مصنفة عند موضعها، لا شاشة موحّدة تُلصق بكل خطوة. تظلّ معرفة موضع الرحلة من عناوين `ScreenFrame` والرجوع واتجاه الحركة، وتُعلن الحالات عبر العناصر الدلالية الموجودة.

## اختبارات وحدود الإثبات

- `shell/no-welcome-flash.test.tsx`: يثبت أن أول خرج لـ`Shell` في `booting` ولـ`RoleRouter` في `resolving` هو هيكل تحميل، لا ترحيباً ولا الرئيسية ولا التسجيل. ويثبت تكرار قرار توجيه الراكب النشط.
- `surfaces/rider/rider-root-screen-stack.test.tsx`: يثبت انتقالات المخفّض `push/pop` وحركاتها، بنية RootTabBar ووسوم اللغات، عقود وصل RiderRoot، وغياب زر رجوع داخلي بلا callback.
- `destination/destination-view.test.ts` و`quote/quote-view.test.ts`: تغطيان نتائج الوجهة الفارغة والرفض المعروف/المجهول، أسباب رفض الموقع، أخطاء API وإعادة المحاولة، حالات عروض الخدمة الفارغة/غير المتاحة، وامتناع المدّة المجهول.
- اختبارات R0/R1 والحالات في `identity/boot.test.ts` و`routing/role-route.test.ts` و`system/screens.test.tsx` باقية في مواضعها.
- الاختبارات هنا تصيير HTML ثابت ومخفّض نقي وقراءة عقود المصدر. لا يدّعي هذا ADR تفاعلاً على DOM حيّ أو قياساً في عميل تيليجرام حقيقي.

## CSS والأثر

توجد أصناف `app-frame`, `app-frame__content`, `app-frame__tabs`, `app-frame__tab`, و`app-frame__screen` وحركات RTL وتقليل الحركة مسبقاً في `global.css`؛ لم يلزم تعديل CSS أو إضافة بادئة. التغيير عرضيّ في الواجهة، ولا يمس API أو العقود أو الخادم أو شاشات R6+.

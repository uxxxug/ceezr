# ADR 0198 — عطلُ Bot API لتيليجرام لا يُسقِطُ مساراتِ Mini App بعدَ المصادقةِ

**الحالة**: مقبول — 2026-09-26 · قرارُ منفِّذٍ ضمنَ التفويضِ الفنّيِّ · الشقُّ المملوكُ للمستودَعِ من `F11-05`
**السياق**: `F11-05` · `TG-004` · `ARCH-014` · `DEC-07` · `F8-05` (ADR 0111) · `ح-4` · `ح-5` · `ح-7` · `ح-8`

## السياقُ

`F11-05` يطلبُ إثباتَ أنَّ توقُّفَ Bot API لتيليجرام لا يُسقِطُ المساراتِ الحيّةَ في Mini App. والشقُّ
المملوكُ للمستودَعِ ههنا **ليس حلَّ `TG-004`/`ARCH-014`** — فتلك تتطلّبُ مصادقةً بديلةً ونشراً حيًّا
عبرَ `DEC-07` — بل إثباتُ أنَّ:

١. **جلسةُ Waslah الداخليّةُ القائمةُ تستمرُّ**: جلسةُ Mini App تُصدَرُ عبرَ `POST /v1/session/telegram`
   التي تُتحقَّقُ من `initData` محليّاً بـHMAC لا تنادي Bot API. فانقطاعُ Bot API لا يُبطِلُ الجلسةَ
   القائمةَ.

٢. **مساراتُ Mini App بعدَ المصادقةِ لا تنتظرُ Bot API**: `GET /v1/me` و`GET /v1/rides/:id` و
   `GET /v1/rides` و`POST /v1/safety/sos` كلُّها تقرأُ من PostgreSQL عبرَ Waslah الداخليّةِ،
   ولا تنادي تيليجرام. فالاستغاثةُ (`F8-05` · ADR 0111) معزولةٌ أصلًا: مسارُ البوتِ قائمٌ ومستقلٌّ،
   وسطحُ Mini App ثانٍ على الحاكمِ نفسِه لا بديلٌ عنه.

   > **تصحيحٌ 2026-09-26 (`ح-8`)**: كُتِبَ هنا أوّلًا `GET /v1/rides/active` و`GET /v1/rides/history` —
   > وهما لا وجودَ لهُما في `apps/gateway/src/routes`. والمسارانِ المقيسانِ في الاختبارِ هُما
   > `GET /v1/rides/:id` (الرحلةُ بمعرِّفِها) و`GET /v1/rides` (السجلُّ بترقيمِ مفتاحٍ).

٣. **فشلُ الإشعارِ معزولٌ ومرئيٌّ**: الإشعاراتُ تخرجُ عبرَ `outbox` → مُرسِلٌ مُغلَّفٌ بـ
   `withOutboundResilience` (إعادةُ محاولةٍ · حدٌّ · طابورُ موتًى · قاطعُ دائرةٍ). والقاطعُ
   (`DEPENDENCY_BUDGETS.telegram`: `failureThreshold` ١٠ · `windowMs` ٣٠ ثانية) يفتحُ بعدَ تكرارِ
   الفشلِ فيمنعُ التتالي. فالإشعارُ لا يُسقِطُ مسارًا ولا يُسكَّتُ بل يُرفَضُ بالقاطعِ ويُسجَّل.

## القرارُ

١. **حقنُ العطلِ على السِلكِ لا بمزدوجٍ**: المُرسِلُ الفاشلُ يُنشَأُ عبرَ
   `createTelegramApi(token, { fetchImpl: deadFetch })` حيثُ `deadFetch` ترفُضُ فورًا بعطلِ اتصالٍ.
   والعطلُ يمرُّ عبرَ المسارِ كاملِه: grammY ← `createGuardedFetch` ← `deadFetch` ← رفضٌ فوريٌّ ←
   القاطعُ يسجِّلُ الإخفاقَ ← بعدَ عشرةِ إخفاقاتٍ يُفتَحُ القاطعُ. وهذا أعلى من «المُرسِلُ الصامتُ»:
   فالصامتُ لا يُحاولِ الإرسالَ أصلاً، فلا يُختبَرُ العزلُ ولا القاطعُ.

٢. **حَكَمٌ خالصٌ لا توكيداتٌ مبثوثةٌ** (`scripts/lib/telegram-outage.ts`): سبعُ قواعدَ —
   `miniapp.api-reachable` · `miniapp.session-valid` · `miniapp.baseline-healthy` ·
   `commercial.state-intact` · `sender.actually-failed` · `breaker.opened` · `sender.failure-visible`.
   والسالبةُ `sender.actually-failed` حرّةٌ: اختبارٌ يمرُّ لأنَّ المُرسِلَ صامتٌ لا فاشلٌ يُقرأُ
   «صمدَ أمامَ العطلِ» وهوَ لم يُحاولِ الإرسالَ أصلاً.

٣. **القاطعُ مفتوحٌ شرطٌ لا نتيجةٌ**: الحَكَمُ يشترطُ أنَّ القاطعَ `open` بعدَ العطلِ. فانغلاقُه
   يعني أنَّ الفشلَ لم يتكرَّرْ بما يكفي لفتحِه، فالعزلُ غيرُ مُختبَرٍ. وفتحُه يعني أنَّ النظامَ
   رأى العطلَ وفصلَ القناةَ — وهوَ عينُ السلوكِ المطلوبِ.

٤. **`withOutboundResilience` بذاكرةٍ محلّيّةٍ وتراجعٍ سريعٍ**: الاختبارُ يُنشِئُ `outboundResilience`
   بـ`redis: null` (ذاكرةٌ محلّيّةٌ) و`baseBackoffMs: 1` و`maxBackoffMs: 10`. فالإنتاجُ يستخدمُ Redis
   متعدِّدَ العملياتِ، والاختبارُ يستخدمُ ذاكرةً لنسخةٍ واحدةٍ — والقاطعُ في `DependencyGuard` مشتركٌ
   بينهما.

## البدائلُ المرفوضةُ

- **مزدوجٌ يُرجِعُ `Result.err`**: لا يُمرَّر عبرَ القاطعِ ولا يسجِّلُ إخفاقًا، فالقاطعُ لا يُفتَحُ
  والعزلُ غيرُ مُختبَرٍ. مرفوضٌ.
- **`silentTelegramSender`**: لا يُحاولِ الإرسالَ أصلاً، فالسالبةُ `sender.actually-failed` تُدينُه.
  مرفوضٌ.
- **حقنُ العطلِ عبرَ `config.telegramTransport = "silent"`**: يُسقِطُ المُرسِلَ من التركيبِ لا
  يُحقَنُ العطلُ على السِلكِ. مرفوضٌ.
- **اختبارُ `outbox` كاملًا**: يتطلّبُ عاملًا خلفيًّا وRedis وانتظارَ تسليمٍ. والعزلُ يُقاسُ على
  السِلكِ لا في الانتظارِ. مرفوضٌ للقياسِ ههنا (موضعُه `F9`/`F10`).

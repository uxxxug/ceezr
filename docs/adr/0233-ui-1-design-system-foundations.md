# ADR 0233: UI-1 / PR 0 — أسسُ نظامِ التصميمِ (قراراتٌ + اختبارُ تباينٍ + جردُ أسطحٍ)

**الحالة:** مقبول
**التاريخ:** 2026-10-06
**المرحلة:** WASLA UI/UX REFOUNDATION — UI-1 (Design System) · PR 0
**المرجع:** `docs/UI_UX_CANONICAL_DIRECTIVE.md` §0–§4 و§11 (صفُّ PR 0) · ADR 0232
**Work Packet:** `docs/work-packets/ui-1-pr0-foundations.json`

## السياق

خطةُ §11 تجعلُ PR 0 «قرارات ADRs + اختبار تباين + جرد أسطح»، وشرطُ قبولِه «بوابات
خضراء بلا تغيير بصري». ولا يوجدُ اليومَ في `apps/miniapp/src/styles/global.css` أيٌّ من
ألوانِ Layer 2 (قِيسَ في 2026-10-06: لا وجودَ لأيِّ قيمةٍ من §2 في `apps/` أو `packages/`).
فالتباينُ يجبُ أن يُقاسَ **قبلَ** أن تُكتبَ الرموزُ في PR 1.

## القرارات

### 1. النطاق

PR 0 لا يُغيّرُ أيَّ ملفٍّ تحتَ `apps/` ولا `packages/`. يضيفُ حاجزَين وثيقتَين فقط.
الرموزُ وكتلُ `ui-*` والأيقوناتُ وآليّةُ التغذيةِ الراجعةِ = PR 1، ولا تبدأُ هنا.

### 2. اللوحة (Layer 2)

القيمُ هيَ جدولُ §2 في الدليلِ حرفاً، ومُعلَنةٌ في `scripts/lib/ui-contrast.ts`
(`LAYER_TWO_PALETTE`). الحاجزُ يُسقِطُ أيَّ انجرافٍ بينَ الاثنين. PR 1 يقرأُ اللوحةَ من
هذا المصدرِ ولا يكتبُ قيمةً ثالثةً.

`mute` ليسَ له قيمةٌ ثابتةٌ في §2 (الخانتان «—»). **القرار:** `mute` = نصٌّ ثانويٌّ من
Layer 1، أي `--tg-hint-color`، فيتبدّلُ مع سمةِ المستخدمِ كبقيّةِ المحايدات.

### 3. قاعدةُ الاستعمالِ والتباين

بحسبِ §2 («اللونُ الدلاليُّ لا يُوضعُ نصّاً مباشراً على سطحٍ مجهولٍ»)، لونُ Layer 2
يُستعمَلُ **تعبئةً** لشارةٍ أو كتلةٍ، والنصُّ فوقَها لونُ «on» معلنٌ يحقّقُ **≥ 4.5:1**
(WCAG 2.x AA للنصِّ العاديّ):

| السمة | brand | amber | ok | bad |
|---|---|---|---|---|
| داكن | `#0f172a` (6.40) | `#0f172a` (9.62) | `#0f172a` (9.29) | `#0f172a` (5.12) |
| فاتح | `#ffffff` (6.29) | `#0f172a` (8.75) | `#ffffff` (5.42) | `#ffffff` (5.62) |

**مقيسٌ ومُلزِمٌ:** amber الفاتحُ (`#F5A524`) مع نصٍّ أبيضَ = 2.04:1، ومع سطحٍ أبيضَ =
2.04:1. فهوَ لا يُستعمَلُ نصّاً ولا مؤشّراً بلا نصٍّ على سطحٍ فاتحٍ. يُستعمَلُ تعبئةً ونصُّها
داكنٌ. وكلُّ حالةٍ تحملُ نصّاً وأيقونةً (§2)، فلا يُعتمَدُ على حدودِ الشارةِ وحدَها.

السطوحُ المقيسةُ هيَ **افتراضاتُ Layer 1 المعلنةُ في `global.css`** وحدَها. سماتُ تيليجرام
الحيّةُ تتبدّلُ ولا تُقاسُ هنا، ولهذا كانَ القرارُ تعبئةً بنصٍّ معلنٍ لا نصّاً على سطحٍ مجهول.

### 4. إخفاقٌ قائمٌ مُسجَّلٌ ولا يُعالَجُ في PR 0

`mute/light/secondaryBg`: `#64748b` على `#f1f5f9` = **4.34:1 < 4.5:1**. هذا قائمٌ اليومَ في
`global.css`، ولا يُعالَجُ هنا لأنَّ PR 0 بلا تغييرٍ بصريّ. يُؤكَّدُ حرفيّاً في `KNOWN_FAILURES`:
إخفاقٌ جديدٌ يُسقِطُ، وزوالُ هذا الإخفاقِ دونَ تحديثِ القائمةِ يُسقِطُ أيضاً. علاجُه قرارٌ في PR 1.

### 5. جردُ الأسطح

السجلُّ في `scripts/lib/ui-surface-inventory.ts`، ومقابَلٌ بالقرصِ في
`scripts/check-ui-surface-inventory.ts`. الملخّصُ في `docs/UI_SURFACE_INVENTORY.md`.

**ما لا يفعلُه الجردُ:** لا يُسنِدُ أرقامَ R0–R15 وD0–D14، لأنَّ تعريفَها في PDF v2.0 وهوَ
ليسَ في المستودع. ولا يُصنِّفُ [A/B/C/D] لكلِّ ملفٍّ. الإسنادُ يحتاجُ المصدرَ، وليسَ عملَ PR 0.

### 6. موضعُ المكوّنات

مكوّناتُ `ui-*` (§4) تسكنُ `apps/miniapp/src/system/ui/` (المجلّدُ غيرُ موجودٍ اليومَ، وينشأُ
في PR 1). المجلّدُ `apps/miniapp/src/system/` قائمٌ ويبقى كما هو.

### 7. ما يبقى ثابتاً (من §0)

لا مكتباتٍ جديدةً. CSS مسطّحٌ بلا `@layer` ولا تداخلٍ ولا `!important`. ملفّاتُ
`*contract.ts` و`*api.ts` و`*view.ts` لا تتغيّر. لا إضعافَ لـCSP/CSRF/authorization.

## العواقب

- حاجزان جديدان في `bun run ci` وفي `.github/workflows/ci.yml`، ولكلٍّ منهما اختبارُ سقوطٍ
  بسالبات.
- PR 1 يبدأُ من لوحةٍ مقيسةٍ وجردٍ مطابقٍ للقرصِ، ويُحدّثُ السجلَّ إذا أضافَ سطحاً أو حذفَه.
- يبقى مفتوحاً: إسنادُ R/D (يحتاجُ PDF v2.0)، وعلاجُ `mute/light/secondaryBg` (PR 1).
